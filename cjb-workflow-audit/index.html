Executive Summary

Mailchimp CJB is functional but riddled with usability friction across every stage.

This audit extends the initial marketer audit with 7 new automated test cases covering template discovery, branching logic, SMS multi-channel, flow settings, validation, activation gates, and active flow analytics. We found 12 new issues (4 usability, 3 barriers, 3 bugs, 2 structural gaps) across all 8 workflow stages. Two areas passed cleanly: the validation checklist and SMS availability. The dominant pattern: features exist but are hard to discover, hard to configure, and hard to trust.

Methodology

Approach: Automated browser walkthrough on live Mailchimp account (Goodnight Fox, us17 datacenter). 7 test cases mapped to all 8 CJB workflow stages. All screenshots captured from live session. Flow 9171 (Scrawler_Ecom_Welcome_FirstPurchase) used for tests 2–6; Bloom Town Launch (9163) for test 7. Draft-only — never activated.

Extends: CJB Marketer Audit which found 10 issues across trigger, delay, email builder, and template UX. This audit covers the remaining untested stages.

Taxonomy: 8-stage CJB workflow: Discover → Define → Design → Compose → Target → Validate → Activate → Monitor. Classification: Bug (incorrect behavior), Barrier (blocks getting started), Usability (slows progress), Launch-blocker (prevents confident activation).

Test 1: Template Gallery — Stage 1 (Discover)

01 Template Gallery — Full page with filters P2 Usability
Test action
Click "Choose flow template" from automations page
What we see
Full-page template gallery at /customer-journey/explore/ with Channels/Topics/Apps & Integrations filters and Sort By dropdown. 80+ templates across 6 categories.
P2 Usability: No search bar for templates

The template gallery has filter dropdowns (Channels, Topics, Apps & Integrations) but no free-text search. A marketer who knows they want a "birthday" or "win-back" template must browse through 80+ cards across 6 category sections. Klaviyo provides instant search with type-ahead.

02 Topics Filter — No B2B/ProServ/Appointment category P2 Barrier
Test action
Open Topics filter dropdown
Available topics
Audience management, Ecommerce, Events, Feedback, General, Special dates, Split test, Transactional
P2 Barrier: Topics taxonomy excludes ProServ/B2B/Appointments

The 8 topic categories heavily skew e-commerce and transactional. There is no "B2B", "Professional Services", "Appointments", "Lead Nurture", or "SaaS" topic. Non-DTC users must browse "General" or start from scratch. One template ("Remind contacts about appointments or reservations") exists but is buried deep in the "Nurture leads" category with no topic filter to surface it.

P3 Usability: Categories repeat "AI-powered" and regular versions of same 3 templates

The first two sections — "Based on your Stripe store" and "All AI-powered flows" — show identical Welcome/Abandoned Cart/Win-back templates. This creates visual clutter and the impression that CJB only has 3 core flows.

Test 2: If/Else Branching — Stage 5 (Target/Personalize)

03 Flow Map sidebar — Drag-and-drop step palette P2 Usability
Test action
Open flow 9171, view sidebar step palette
Available steps
Rules: If/Else, Split Path, Wait for trigger, Time delay. Actions: Send email, Send SMS, Webhook, Send survey in email, Group/Ungroup, Tag/Untag, Unsubscribe email, Update contact, Archive contact
P2 Usability: Sidebar steps are drag-and-drop only — no click-to-add

The sidebar palette shows step cards with grip handles, implying drag-and-drop. Clicking a sidebar card activates it but the user must then locate a "+" zone on the canvas to drop it. The alternative: click a "+" on the canvas, which opens a dropdown. Two different interaction models for the same action creates confusion. Browser automation could not reliably use drag-and-drop, confirming this is a barrier for accessibility and keyboard-only users.

04 Canvas step picker — Inline dropdown after clicking "+" Pass
Test action
Click "+" button on canvas between steps
What happened
"Select a step to add" dropdown appeared with all available Rules and Actions. "Send SMS" labeled "New", "Webhook" labeled "Beta". Clean, accessible interaction.
Pass: Canvas "+" picker works well

The inline dropdown is accessible, keyboard-navigable, and labels new features clearly. This should be the primary step-add pattern; the drag-and-drop sidebar should be secondary.

05 If/Else Segment Builder — Condition categories P2 Usability
Test action
Add If/Else step to flow, view available conditions
Available conditions
Tags: Tags. Groups: Content/Product interest. Contact details: Address, Company, Contact rating, Email, Language, Phone, Predicted age/gender/location, VIP status. Engagement: Automation activity, Email/SMS subscription & interaction, Conversations. E-commerce: Amount spent, Products purchased, Purchase activity/date, Total orders.
P2 Usability: If/Else opens full Segment Builder modal — heavyweight for simple branching

Adding an If/Else rule opens Mailchimp's full-page Segment Builder modal (same as audience segmentation). For a simple branch like "has tag X" or "opened previous email", this is overwhelming. The filter list mixes account-specific merge fields (e.g., "How old is your toddler?", "Yotpo", "Yotpo 2", "Yotpo 3") with system conditions, making it hard to find standard branching options. Klaviyo uses a focused inline condition picker within the flow canvas.

Positive: The search field ("Select or search a filter") does work — you can type to filter conditions. This is a notable improvement over the trigger picker which has no search.

06 If/Else on canvas — Yes/No branching Pass
Test action
Cancel segment builder to see If/Else node on canvas
What we see
If/Else step appears with "Choose 1 or more conditions" prompt and Yes/No branch labels. Warning icon shows unconfigured state. Manage Step context menu has Pause, Edit, Copy, Delete.
Pass: If/Else branching renders clearly on canvas

The Yes/No branches are visually clear and the warning icon correctly indicates an unconfigured state. The context menu (Pause, Edit, Copy, Delete) provides expected management actions.

Test 3: Turn On Attempt — Stage 7 (Activate)

07 Automation Flow Review — Validation checklist P2 Usability
Test action
Click "Continue" button in flow builder header
What happened
"Automation flow review" modal appeared with validation checklist: Trigger configured ✅, Flow settings configured ✅, "Please make sure this email's content is not empty" ❌, "Plus 2 other issues"
P2 Usability: Validation hides errors behind "Plus N other issues" collapse

The validation checklist correctly identifies that the flow is not ready (trigger OK, settings OK, email content empty). However, it only shows the first error and hides additional issues behind "Plus 2 other issues" — without expanding them automatically. A marketer cannot see the full list of what needs fixing without extra clicks. The "Go to issue" button navigates to the first error only.

Positive: The validation checklist does exist and correctly blocks activation of incomplete flows. This is a significant improvement over what we observed in the earlier audit, where the Continue button's state was opaque. The validation is the right pattern; it just needs to show all issues upfront.

P3 Barrier: "Edit" vs "Go to issue" buttons are ambiguous

The review modal shows "Edit" (returns to flow builder) and "Go to issue" (navigates to first error). A marketer who wants to fix all issues in sequence has no "Fix all" path — they must fix one issue, click Continue again, and re-run validation.

Test 4: Flow Settings — Stage 6 (Validate)

08 Flow Settings panel — Name, objective, logic, tracking P3 Usability
Test action
Click Settings tab in left sidebar
Settings available
Name & objective: Flow name, Marketing objective (No objective/Nurture relationships/Sell stuff/Drive audience action/Share information/Manage audience/Re-engage/Something else). Logic: Re-entry toggle, Exit condition dropdown. Contact management: Manually add/remove contacts. Tracking: GA link tracking, Track clicks, Track opens.
P3 Usability: Missing settings a marketer would expect

Present: Name, objective, re-entry, exit condition, manual contact add/remove, GA tracking, click/open tracking. Missing: Send time optimization (Smart Send Time), send throttling/rate limiting, A/B test configuration at the flow level, flow-level scheduling (business hours only), UTM parameter customization, quiet hours configuration for the flow (only available per-SMS step). Compared to Klaviyo's flow settings which include Smart Send Time, throttling, and skip-on-recent-email rules, Mailchimp's settings are basic.

Test 5: SMS Step — Stage 3 (Design Multi-Channel)

09 Send SMS configuration — Step added to flow Pass (with caveats)
Test action
Add Send SMS step from canvas "+" picker
SMS configuration
Title: "Untitled SMS message" with Edit name link. Send time: "As soon as possible, outside of quiet hours" with View button. Content: "Write your message" with Edit content button. Preview: Shows account phone number (+1-925-750-3995) and default message "Kylie at Goodnight Fox: Text STOP to opt out".
Pass: SMS is available in CJB flows

SMS steps can be added to CJB flows from the canvas picker. The step is labeled "New" confirming recent addition. The configuration modal shows send time, content editing, and a real-time preview with the account's registered phone number. No separate SMS opt-in setup is required inline — it uses the account's existing SMS program.

P3 Usability: SMS content editor is minimal compared to email

While email steps offer a full visual builder with templates, the SMS step provides only a text-entry field with a character counter. No merge tag assistant, no link shortener preview, no A/B testing of SMS variants. The "quiet hours" setting is appreciated but not configurable per-flow (only per-step).

Test 6: Contact Exit Rules — Stage 2 (Define)

08b Exit Condition — Buried in Settings, not on canvas P2 Barrier
Test action
Look for exit/removal rules on flow canvas and Settings panel
What we found
Exit condition is in Settings panel under "Logic settings" — dropdown with "Reaches the end of the flow" as default. Canvas shows "Contact exits" label at bottom but clicking it does nothing.
P2 Barrier: Exit conditions are limited and buried

The exit condition dropdown offers only "Reaches the end of the flow" by default. There is no obvious way to set exit-on-event (e.g., "exit if contact makes a purchase", "exit if contact unsubscribes"). Klaviyo allows setting specific goal events that automatically remove contacts from a flow when achieved. In Mailchimp, the "Contact exits" label appears on the canvas but is non-interactive — a marketer cannot click it to configure exit rules. This is a significant gap for e-commerce flows where purchase-based exit is essential.

Test 7: Active Flow Analytics — Stage 8 (Monitor)

10 Flow Report — Bloom Town Launch analytics P2 Usability
Test action
Click "View Report" on active Bloom Town Launch flow (9,061 contacts completed)
Metrics shown
Header: Active status, start date, days active (22), total started (9,061), in progress (0), completed (9,061). Date range: 05/04–05/26/2026 with bot filtering. Performance: Revenue (--), Revenue per recipient ($0), Order rate (0%), Click rate (0.44%).
P2 Usability: Flow report lacks actionable insight for marketers

The flow report shows basic throughput metrics (started/in-progress/completed) and e-commerce performance (revenue, order rate, click rate). However:

• No per-step metrics: Cannot see which email in the flow performs best. No step-level open/click rates on the report page.
• No conversion funnel visualization: No visual showing drop-off between steps. Klaviyo shows a flow-level funnel with conversion rates at each node.
• Revenue shows "--" even for e-commerce flows: With 9,061 completed contacts and 0% order rate, the revenue display shows "--" instead of "$0" — inconsistent with the $0 revenue-per-recipient.
• No comparison to benchmarks: 0.44% click rate has no context. Is this good or bad for this type of flow?
• No "next action" recommendations: No AI-powered suggestions for improving the flow's performance.

Cross-Cutting Themes

Theme 1: Discovery > Discoverability. Features exist (SMS, If/Else with rich conditions, validation checklist, exit conditions) but are hard to find. The most common user paths bury capabilities behind non-obvious UI patterns (drag-and-drop, collapsed sections, Settings panel).

Theme 2: E-commerce bias pervades every stage. Templates, topics, suggested triggers, reporting metrics — all assume DTC/e-commerce. ProServ, B2B, SaaS, and appointment-based businesses are underserved at every touchpoint.

Theme 3: Monitoring is the weakest stage. Flow analytics show aggregate throughput and e-commerce revenue but lack step-level performance, funnel visualization, benchmark comparisons, and actionable recommendations. This makes CJB a "set and forget" tool rather than an optimization platform.

Combined with marketer audit: Across both audits, 22 total issues found. The binding constraint is not feature availability but activation friction — consistent with the product health data showing 33.6% activation rate and 40.2% churn.
