What Was Tested

The Standard Email Editor — Mailchimp's drag-and-drop block builder accessible via the Email Templates page. This is not the default "Create email" or "Design email" path, which now routes to the AI Chat Editor (Unified Builder).

Explored

  • Template discovery via Email Templates page
  • Editor entry through "Create from scratch"
  • Full block library (15 content blocks)
  • Section management (Header, Body, Footer)
  • Global style controls (Background, Text, Link, Button, Divider, Image, Logo)
  • Typography system (P, H1–H4) with device-specific sizing
  • Preview modes (Desktop, Mobile, Inbox)
  • Send Test Email dialog

Key Discovery

The Standard Editor is NOT accessible from the primary email creation flow.

  • "Create email" → routes to AI Chat Editor
  • "Design email" → routes to AI Chat Editor
  • Standard Editor only accessible via Email Templates page — a separate, non-obvious path
  • Template editor creates templates, not campaigns — users must create a template first, then create a separate campaign from it

Top 5 Issues

High SE-001: Standard editor is hidden from primary email creation flows

The drag-and-drop block editor is not accessible from "Create email" or "Design email" buttons. Users must navigate to Email Templates — a separate, less discoverable page — to reach it.

High SE-015: Template → Campaign disconnect adds unnecessary steps

Creating a template does not create a campaign. Users must navigate to Campaigns → Create email → select template, adding a multi-step detour that breaks the creation flow.

Medium SE-008: No inline AI content generation in block editor

AI-Generated Columns exist as pre-structured layouts (Article summary, Upcoming event, Product promotion) but offer no generative AI — no "write this for me" capability within blocks.

Medium SE-005: Email canvas in iframe blocks standard DOM interactions

The email canvas renders inside an iframe, meaning sidebar blocks cannot interact with canvas elements through standard DOM events. This architectural choice limits extensibility.

Medium SE-016: Three builder entry points without clear differentiation

"Create from scratch", "Create a legacy template", and "Code your own" are presented side by side without explaining what each produces or when to use which.

Verdict: Capable Builder, Broken Workflow

The Standard Editor is a mature, full-featured block builder with 15 content blocks, comprehensive style controls, device-specific typography, and a clean 3-mode preview. It is significantly more reliable and controllable than the AI Chat Editor. However, it is effectively hidden from users — buried behind Email Templates with a disconnected template-to-campaign workflow. The editor itself is solid; the problem is that users can't find it and can't use it efficiently.

Complete Issue Inventory

Issue Log — 17 Findings

All issues discovered during the Standard Editor UX evaluation, with severity, type, and evidence

Discovery & Navigation Issues

High SE-001: Standard editor is hidden from primary email creation flows

Type: Usability Category: Discovery Location: Email Templates page

Description: The Standard Editor (drag-and-drop block builder) is not accessible from "Create email" or "Design email" in the campaign flow. These buttons now route exclusively to the AI Chat Editor. The only path to the Standard Editor is via Email Templates — a separate page that requires intentional navigation.

Expected: Users should be able to choose between AI-assisted and manual editing from the primary campaign creation flow.

Actual: AI Chat Editor is the only option from campaign creation. Standard Editor requires navigating to a separate templates section.

Impact: Users who prefer manual control, have established template workflows, or need the block editor for complex layouts cannot reach it from the natural email creation path. Agencies and power users most affected.

Recommendation: Add a "Build manually" or "Use template builder" link alongside the AI Chat Editor entry point in the campaign flow.

Medium SE-002: "Create from scratch" button becomes disabled after click

Type: Usability Category: Discovery Location: Email Templates → Create from scratch button

Description: After clicking "Create from scratch", the button becomes disabled. It's unclear whether this is a loading state (editor is loading in background), a single-use restriction, or a bug.

Expected: Clear loading indicator (spinner, "Opening editor...") if the button triggers navigation, or the button should remain clickable.

Actual: Button grays out with no loading feedback. User is left wondering if their click registered.

Impact: First-time users may click repeatedly, assume the feature is broken, or abandon the flow.

Recommendation: Add a loading spinner or "Opening editor..." text when the button is processing. If the editor opens in a new context, navigate immediately.

Medium SE-003: Template editor creates templates, not campaigns

Type: Usability Category: Discovery Location: Standard Editor → template context

Description: The Standard Editor accessed via Email Templates creates a template — not a campaign. The title bar reads "Template: Untitled Template" and saving produces a template, not a sendable campaign. Users must separately create a campaign and select this template.

Expected: Creating email content should result in a sendable email, or the template-to-campaign connection should be seamless.

Actual: Two separate workflows: (1) create template in Standard Editor, (2) create campaign in Campaigns, (3) select the template. This is a 3-step process for what should be 1 step.

Impact: Users unfamiliar with Mailchimp's template/campaign distinction may design an email and not understand why they can't send it directly. Adds friction to the entire email creation workflow.

Recommendation: Offer "Save as template" and "Create campaign from this template" as dual save options. Or allow the Standard Editor to be invoked from within the campaign creation flow.

Low SE-004: No click-to-insert for blocks — drag-and-drop only

Type: Usability Category: Discovery Location: Standard Editor → Blocks panel

Description: Blocks can only be added to the email canvas via drag-and-drop. There is no click-to-insert or "Add block here" mechanism at insertion points in the canvas.

Expected: Both drag-and-drop and click-to-insert should be available. Many users prefer clicking, especially on touch devices or when using assistive technology.

Actual: Drag-and-drop is the sole insertion method.

Impact: Accessibility limitation for users who cannot perform drag operations. Minor efficiency issue for keyboard-primary users. Both Klaviyo and Shopify support click-to-insert.

Recommendation: Add insertion point markers on the canvas that expand on hover, showing an "Add block" button. Clicking opens a quick-select menu of block types.

Medium SE-005: Email canvas in iframe limits interaction patterns

Type: Usability Category: Discovery Location: Standard Editor → Canvas area

Description: The email canvas renders inside an iframe. While this provides accurate email rendering, it means sidebar blocks cannot interact with canvas elements through standard DOM events. Cross-iframe drag-and-drop requires special handling.

Expected: Seamless interaction between sidebar panel and canvas elements regardless of rendering architecture.

Actual: Iframe boundary creates interaction constraints. Drag operations must cross iframe boundaries, which can cause jank or dropped interactions on slower connections.

Impact: Occasional drag-and-drop failures. Limits extensibility for future features. Makes browser automation and testing more complex.

Recommendation: Consider migrating to a shadow DOM approach that provides style isolation without iframe interaction constraints, or ensure robust cross-iframe message passing for all interaction types.

Content & Editing Issues

Medium SE-006: "Start typing..." placeholder lacks context

Type: Usability Category: Content Location: Standard Editor → Canvas default state

Description: The default canvas state shows "Start typing..." as placeholder text. This doesn't indicate what to type, where blocks should be placed, or how to build the email structure.

Expected: Contextual onboarding: "Drag a block from the left panel to start building your email" or an interactive guide overlay for first-time users.

Actual: Generic "Start typing..." that implies the canvas is a text editor rather than a block-based builder.

Impact: First-time users may try typing directly into the canvas rather than using blocks. Misaligns mental model with the builder's interaction paradigm.

Recommendation: Replace with "Drag a content block here to get started" or add a contextual tooltip/overlay on first load.

Low SE-007: 6 blocks hidden behind "Show more"

Type: Usability Category: Content Location: Standard Editor → Blocks panel

Description: 6 of 15 content blocks (Survey, Code, Apps, Product, Product Rec, Footer) are hidden behind a "Show more" link. Product and Product Rec blocks are particularly important for e-commerce users.

Expected: All blocks visible, or at minimum e-commerce blocks (Product, Product Rec) should be in the primary visible set.

Actual: Only 9 blocks visible by default; 6 require clicking "Show more" to discover.

Impact: E-commerce users may not discover product-specific blocks. Reduces feature discoverability for power blocks like Code and Apps.

Recommendation: Either show all 15 blocks (scrollable panel) or dynamically prioritize blocks based on user's business type (e.g., show Product first for e-commerce accounts).

Medium SE-008: No inline AI content generation

Type: Missing Feature Category: Content Location: Standard Editor → Blocks panel → AI-Generated Columns

Description: "AI-Generated Columns" are labeled as "New" and include three pre-structured layouts (Article summary, Upcoming event, Product promotion). However, they are static layout templates — not generative AI. No block offers "write this for me", "generate subject line", or any LLM-powered content assistance.

Expected: AI-Generated Columns should either generate content based on user context, or the editor should offer inline AI writing assistance (similar to Klaviyo's AI subject lines or Shopify's Sidekick content generation).

Actual: Template-only layouts with placeholder text. The "AI-Generated" label is misleading.

Impact: Users expecting AI assistance within the block editor will be disappointed. Creates a confusing gap between the AI Chat Editor (fully AI-driven) and the Standard Editor (zero AI assistance). Competitors offer inline AI as a middle ground.

Recommendation: Add an "AI assist" button within text blocks that can generate, rewrite, or expand content. Rename "AI-Generated Columns" to "Pre-built Layouts" or add actual generative capability.

Low SE-009: "How to use this builder" link is small and easy to miss

Type: Usability Category: Content Location: Standard Editor → Top bar

Description: A "How to use this builder" link appears in the top bar of the editor but is rendered in small, unemphasized text that blends with the interface chrome.

Expected: First-time users should see a prominent onboarding prompt or interactive walkthrough. The help link should be visually distinct.

Actual: Small text link that first-time users may not notice.

Impact: Users who would benefit from the guide may miss it entirely. Low severity because experienced users don't need it.

Recommendation: Show a first-time user tooltip pointing to the link, or trigger an interactive walkthrough on first editor load. Consider a "Take a tour" button with higher visual weight.

Style & Design Issues

Medium SE-010: All style sections collapsed by default

Type: Usability Category: Style Location: Standard Editor → Styles tab

Description: All seven style sections (Background, Text, Link, Button, Divider, Image, Logo) are collapsed when the Styles tab opens. Users must expand each one individually to discover what controls are available.

Expected: At minimum, show a summary of current settings in the collapsed state (e.g., "Helvetica, 16px, #000000"). Consider auto-expanding the first section or the section most relevant to the user's last action.

Actual: Seven collapsed sections with no indication of current settings until expanded.

Impact: Users new to the Styles tab don't know what design options exist without clicking through each section. Reduces discoverability of a strong feature set.

Recommendation: Show inline previews or summaries in collapsed headers. Auto-expand "Text" on first visit as it's the most commonly modified.

Low SE-011: No brand kit auto-application

Type: Usability Category: Style Location: Standard Editor → Styles → Text

Description: The editor defaults to Helvetica for all typography levels even though the account has a Brand Kit configured with specific fonts and colors. Users must manually select their brand fonts for each new template.

Expected: New templates should auto-apply the account's Brand Kit settings (fonts, colors, logo) to reduce manual configuration.

Actual: Generic Helvetica defaults for all text levels. No Brand Kit colors in the palette picker.

Impact: Extra manual work for every new template. Brand consistency depends on user memory rather than system enforcement.

Recommendation: Auto-populate styles from Brand Kit when creating a new template. Offer "Apply Brand Kit" as a one-click action in the Styles panel.

Low SE-012: Device-specific sizing adds complexity

Type: Usability Category: Style Location: Standard Editor → Styles → Text → Device-specific

Description: Desktop and Mobile font sizes are configured separately. While powerful for responsive design experts, this adds complexity for non-expert users who may not understand why they need different sizes for different devices.

Expected: Linked Desktop/Mobile sizing by default with an "Unlink" option for advanced users. Auto-scale mobile sizes from desktop (e.g., mobile = desktop × 0.875).

Actual: Fully independent Desktop and Mobile controls that must both be configured.

Impact: Non-expert users may only configure Desktop sizes, resulting in suboptimal mobile rendering. Low severity because the feature itself is correct — it's the default behavior that could be smarter.

Recommendation: Default to linked sizing with auto-scale. Show an "Advanced: Customize for mobile" toggle for users who want independent control.

Preview & Testing Issues

Low SE-013: Preview shows raw merge tags

Type: Content Category: Preview Location: Standard Editor → Preview → Desktop

Description: The preview mode shows raw merge tags (e.g., *|IFNOT:ARCHIVE_PAGE|*, *|LIST:COMPANY|*) instead of sample data or explanatory text. Non-technical users may not understand what these will resolve to.

Expected: Merge tags should show sample values from the account data (e.g., company name, address) or display explanatory tooltips.

Actual: Raw merge tag syntax displayed verbatim in the preview.

Impact: Confusing for non-technical users. May cause alarm that the email looks "broken." Low severity because the tags work correctly when sent.

Recommendation: Replace merge tags in preview with sample data from the account. Add tooltips explaining each tag's purpose.

Low SE-014: Test email warning without resolution path

Type: Usability Category: Preview Location: Standard Editor → Send a Test Email dialog

Description: "Send a Test Email" dialog warns "Merge tags won't populate content in test emails" but doesn't offer any way to preview the email with populated tags. No link to documentation about how to test merge tags.

Expected: Warning should include a path to resolution: "To preview with real data, use Inbox Preview" or "Send to yourself using the campaign preview feature."

Actual: Warning only, no actionable alternative.

Impact: Users cannot verify merge tag behavior without sending through the campaign flow. Minor friction.

Recommendation: Add a "Preview with sample data" option or link to campaign-level preview that populates merge tags.

Structural Issues

High SE-015: Template → Campaign disconnect adds unnecessary steps

Type: Usability Category: Structural Location: Email Templates → Standard Editor → Campaigns

Description: Creating a template in the Standard Editor does not create a campaign. The user must: (1) design the email in the Standard Editor, (2) save as template, (3) navigate to Campaigns, (4) click "Create email", (5) select their template, (6) configure campaign settings (To, From, Subject), (7) send. This is a 7-step process with a context switch in the middle.

Expected: Email creation should be a linear flow: design → configure → send. Or at minimum, the Standard Editor should offer "Create campaign from this template" as a save option.

Actual: Template and campaign are completely separate workflows with no direct connection from the editor.

Impact: High friction for the core email creation workflow. Users must understand Mailchimp's internal template/campaign abstraction to use the Standard Editor effectively. New users may abandon after creating a template and not understanding how to send it.

Recommendation: Add "Save and create campaign" as a primary save action alongside "Save as template". This creates the campaign with the template pre-loaded and takes the user directly to the campaign checklist.

Medium SE-016: Three builder entry points without clear differentiation

Type: Usability Category: Structural Location: Email Templates page

Description: The Email Templates page shows three creation options side by side: "Create a legacy template", "Code your own", "Create from scratch". There is no explanation of what each option produces, what editor each opens, or when a user should choose one over another.

Expected: Each option should include a brief description or visual preview showing the editing experience it opens. Ideally, deprecated options (legacy) should be visually de-emphasized.

Actual: Three buttons with no context. "Create a legacy template" implies the others are also legacy. "Code your own" is for developers but appears alongside beginner options.

Impact: Users may choose the wrong entry point, create a template in an outdated format, or waste time exploring options. The word "legacy" raises concern about the entire feature's future.

Recommendation: Add subtitle text to each button (e.g., "Create from scratch — Drag-and-drop block editor"). Visually de-emphasize legacy option. Move "Code your own" to an advanced/developer section.

Medium SE-017: "Mailchimp templates" tab unexplored — unclear offering

Type: Usability Category: Structural Location: Email Templates → Mailchimp templates tab

Description: The Email Templates page has a "Mailchimp templates" tab alongside "Saved" and "Recently sent". This tab was not explored during the evaluation. It's unclear whether it offers pre-designed layouts, industry-specific templates, or something else.

Expected: The tab should clearly communicate its value: "Browse 100+ professionally designed templates" or similar.

Actual: Tab label alone doesn't communicate value proposition. Users may not click if they don't understand what it offers.

Impact: Potentially valuable pre-designed templates may go undiscovered. Users may spend time building from scratch when a suitable template already exists.

Recommendation: Add a subtitle or badge (e.g., "100+ designs") to the tab. Show a preview carousel on the Saved tab: "Or start from a Mailchimp template →".

Head-to-Head Evaluation

Standard Editor vs. AI Chat Editor

Side-by-side comparison across 14 dimensions — two editors, fundamentally different paradigms

Strategic Analysis

Standard Editor Strengths

  • Reliability: Zero critical bugs — deterministic behavior
  • Completeness: 15 blocks, 7 style sections, 3 preview modes
  • Control: Full direct manipulation of every element
  • E-commerce: Product and Product Rec blocks
  • Responsive: Device-specific typography controls

Standard Editor Weaknesses

  • Hidden: Not accessible from primary email creation flow
  • Disconnected: Creates templates, not campaigns
  • No AI: Zero AI content assistance in blocks
  • Drag-only: No click-to-insert alternative
  • No Brand Kit: Defaults to generic Helvetica
The Ideal Solution: A unified editor that combines the Standard Editor's reliability, block variety, and style control with the AI Chat Editor's content generation and speed. Users should be able to start with AI for a first draft, then switch to block-level editing for refinement — without switching editors, losing work, or creating duplicate campaigns.

Suggested Experiments

A/B Test: Editor Choice

  • Hypothesis: Showing "AI Editor" and "Block Editor" as equal-weight choices on the campaign creation page will increase overall email completion rate
  • Control: Current AI-only routing from "Design email"
  • Variant: Choice dialog: "Create with AI" vs. "Build with blocks"
  • Metric: Campaign completion rate, time to send

A/B Test: Block Visibility

  • Hypothesis: Showing all 15 blocks by default increases usage of Product, Product Rec, and Survey blocks
  • Control: Current "Show more" gate (9 visible)
  • Variant: All 15 blocks visible in scrollable panel
  • Metric: Block usage diversity, Product block adoption

A/B Test: Brand Kit Auto-Apply

  • Hypothesis: Auto-applying Brand Kit fonts and colors to new templates reduces time to first send and increases brand consistency
  • Control: Current Helvetica default
  • Variant: Brand Kit pre-applied to all style sections on template creation
  • Metric: Time to save template, style modification rate, template reuse rate
