P0 Simple 30 min

  • Attempt to understand AI editor vs traditional editor options
  • Look for alternative non-AI creation paths
What to Test / Observe

Does the user understand they are entering an AI editor? Is the value proposition clear? Can they find an alternative non-AI path?

Expected Bugs

UB-002 Confusion between AI Chat Editor and traditional builder; no explanation of what "Generate emails with Mailchimp AI" means vs traditional editing

Heuristics Evaluated
Visibility of system status Match between system and real world User control and freedom
Evaluation Criteria

  • Clicks required to start creating content
  • Abandonment indicators (back button, hesitation, confusion)

Scoring & Methodology

Evaluation Framework

How to score, aggregate, and report findings from TestJam execution

Scoring Rubric by Dimension

DimensionScore 1 (Fail)Score 2 (Poor)Score 3 (Adequate)Score 4 (Good)Score 5 (Excellent)
Usability Cannot complete task Completes with major confusion/errors Completes with minor friction Smooth flow with minor hesitation Intuitive, delightful flow
Bugs Critical bug blocks task Major bug requires workaround Minor bug, cosmetic impact No bugs, minor edge cases No bugs, graceful edge handling
Heuristics Multiple violations, severe 2-3 violations, significant impact 1-2 minor violations No violations, meets standards Exceeds standards, innovative
Barriers Hard barrier, no path forward Barrier requires external help Soft barrier with visible workaround No barriers encountered Proactive barrier prevention
Frictions 10+ unnecessary steps 5-9 unnecessary steps 2-4 unnecessary steps 1 unnecessary step Optimal path, zero waste

Performance Unusably slow (>30s waits) Noticeably slow (15-30s) Acceptable (5-15s) Fast (2-5s) Instant (<2s), optimistic UI

Aggregation Method

Per Test Case: Score each applicable dimension 1-5. Calculate weighted average:
TC Score = (Usability × 0.25) + (Bugs × 0.25) + (Heuristics × 0.15) + (Barriers × 0.15) + (Frictions × 0.10) + (Accessibility × 0.05) + (Performance × 0.05)

Per Category: Average of all TC scores in category, weighted by priority (P0 × 3, P1 × 2, P2 × 1).

Overall: Weighted average of category scores: Entry (15%) + Content (25%) + Editing (20%) + Preview (15%) + Sending (15%) + Cross-Product (10%).

Priority Definitions

Failures here mean the product cannot be trusted for production use. Includes: data loss, content corruption, dead ends, sending wrong content, blocked completion paths.

TestJam Execution Guardrails

  • Test environment: Use a dedicated test account (e.g., Goodnight Fox us17) to avoid impacting production data
  • Send tests only to controlled addresses — never send test campaigns to real customer lists during evaluation
  • Document everything: Screenshot every step, including successful flows (establishes baseline)
  • One tester per session: Each test case should be run by one person in a single session to maintain consistency
  • Time-box strictly: If a test case exceeds 2x estimated time, mark as BLOCKED and document where you got stuck
  • Fresh state between tests: Clear browser cache and start new session between category groups
  • Reproduce before reporting: Attempt to reproduce any bug at least once before logging; note if intermittent
  • Compare with prior audits: Cross-reference findings with UB Scrawler (14 issues) and Standard Editor (17 issues) reports
  • Qualitative N=1: These are directional findings from expert evaluation, not statistically validated usability studies
